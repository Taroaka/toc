# Sound spotting note

これは人/author向けの記入テンプレート。runtime JSON schemaではない。
必要ならrunの`logs/sound_design/spotting.md`へ保存する。現行生成/配置の正本は`sound_design.json`。
空欄のまま形式的に埋めたり、研究資料をそのままprovider promptへ送ったりしない。

## 全編

- 作品の中心となる変化と結末:
- 観客に最後に残したい受け止め:
- 既存の語り/台詞の担当範囲:
- 音楽が担当する範囲:
- SE/環境音が担当する範囲:
- 音楽を使わない区間と理由:
- 反復する主題/音（使わない場合は不要）:
- 音色・密度・距離の連続性:
- 元動画音声を残す/消す/補う方針:

## 区間ごとの判断

| 対象scene/cutと出来事 | 観客の理解/感情の前→後 | 優先して聞かせるもの | BGM/SE/環境/音を引く判断 | 入る・変わる・終わる合図 | 前後とのつながり |
| --- | --- | --- | --- | --- | --- |
| | | | | | |

## 各cue（必要な数だけ記入）

- 対応する既存cue ID / source_selector:
- 種類（runtimeはbgmまたはse、細分類はメモ）:
- なぜ必要か。消すと何が失われるか:
- 劇中音/観客向け/主観音、誰の知覚か:
- 入る時点・変化点・終わる時点と、その根拠となる出来事:
- 生成する素材の尺 / 最終配置の尺 / 編集用余白:
- 音楽の展開・音数・音色、またはSEの材質・動き・距離:
- 言葉との重なり、聞かせる優先順位:
- 反復元の音源/主題と、変える要素:
- 元動画音声との重複と処置:
- providerに渡す最終prompt:
- 現行のstart_seconds / duration_seconds / volume_db / fades / loopへの対応:
- 未対応の編集が必要な点:
- 採用候補・配置変更・ユーザー意見:

## 比較試聴メモ

- 比較した版と変更点:
- 語りの聞き取り:
- 人物/展開をどう受け取ったか:
- 最後に残った感情（意図と実感を区別）:
- 音が多すぎる/早すぎる/遅すぎる箇所:
- 採用/不採用と理由:

記入しただけでは工程完了にしない。実音源、正式参照、配置、既存の検証・採用・確定が揃ってからstateを更新する。
