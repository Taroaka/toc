# AI広告制作

実務資料の正本は ToC リポジトリの `marketing/AI-ads/`。この環境では `/Users/kantaro/Downloads/toc` にある。インストール先の相対パスではなく、実在するリポジトリから読む。移転していたらユーザー指定の場所を確認する。

1. `marketing/AI-ads/README.md` を読み、作品の視聴促進、ToCサービスの集客、EC販売のどれかを依頼と素材から判断する。以下の表で必要な判断知識を読む。ToCサービスなら `marketing/README.md` と `marketing/first-offer.md` も読み、料金・提供範囲をそちらに合わせる。
2. 指定された作品/run/商品URL/写真/実績を確認する。事実・顧客仮説・実測を分ける。制作を左右する不足だけをまとめて聞き、任意項目は仮定を明記して進める。
3. `templates.md` の必要な型で、ブリーフ、比較する広告案、コピーや台本、テスト条件を案件フォルダに作る。案数は指定・素材・予算に合わせる。固定の大量生成は要求しない。
4. 制作が依頼されたら `production-handoff.md` を読み、利用可能な既存スキル・ツールで実ファイルまで作る。企画だけの依頼なら企画で完了する。プロンプト、コマンド、実行ジョブだけを完成画像・動画として報告しない。
5. 仕上がり、文字・数字・商品との一致、掲載面での見え方を確認する。比較する版に予定外の差がないか確認する。媒体の仕様や表示ルールは実行時の公式資料に照らす。
6. 成果物と根拠・変更点・未確定事項を保存する。実績分析では分母・期間・計測定義を揃え、観測と原因仮説を分け、次に試す変更へ結びつける。

このスキルの読み込みは、広告配信・広告費の使用・外部公開の許可ではない。既存のユーザー許可は引き継ぐ。通常の制作ごとに追加の承認を要求しない。

## 必要な知識の読み分け

以下のパスはすべて `marketing/AI-ads/` からの相対パス。

| 今回の仕事 | 読む資料 |
| --- | --- |
| 曖昧な依頼を整理、出力を修正、案件の知識を再利用 | `knowledge/common.md` |
| 商品・顧客の調査、訴求やブランド方針の選択 | `knowledge/strategy.md` |
| バナーや広告画像 | `knowledge/banner.md`。ブリーフ未作成ならstrategyも読む |
| 動画の台本・素材・冒頭違いの案 | `knowledge/video.md`。ブリーフ未作成ならstrategyも読む |
| キーワード・検索広告文・検索語の改善 | `knowledge/search.md` と `official-checks.md` の該当部分 |
| 結果の評価、次の比較テスト | `knowledge/measurement.md` と対象形式の知識 |
| 教材の特定テーマを確認 | `coverage.md` から対応するローカルの節。出典は `sources.md` |

判断知識を読まず、テンプレートの項目だけを一般論で埋めない。参照した知識ファイルと使用した商品事実を案件の記録へ残す。必要な資料が見つからなければ、教材に基づく判断をしたと偽らず、不足を具体的に伝える。

初回の使い方は `examples.md`、全体の流れは `playbook.md` にある。保存資料から通常の企画・制作を進め、元のビューアーへの再アクセスは必須にしない。原著の特定の文章・既成プロンプト・付属ボットを求められたら、保存してある運用知識と区別する。

教材の数値事例、既成プロンプト、推奨サービスを、その案件の実績・承認済みコピー・固定設定として流用しない。判断できない成果は保留し、制作に使う仮説と観測結果を分ける。
