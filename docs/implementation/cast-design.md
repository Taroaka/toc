# 全キャストの人物設計

個別のキャラ画像を作る前に、作品の全キャストを同じ文脈で設計する。
役割の違う人物が、同じ顔・髪・衣装の組み合わせへ収束することを防ぎ、
人物同士の関係と、観客が誰を見ているかを画面で読み取れるようにする。
作品の共通する美術様式は維持し、全員を無関係な画風に分けない。

## 入力と順序

1. research/storyと全sceneの登場人物を読む。p420で追加された人物も含む最終resource一覧を使う。
   主人公、主要人物、脇役、集合名で扱われる人物、動物、変化後の姿を確認する。
   登場順、共演する相手、似た役割、取り違えると物語の意味が変わる相手を整理する。
2. 既存の合格画像、人物ID、衣装状態と変更不可の特徴を確認する。
   新しい全体設計を理由に、合格済みの顔や衣装を一律で再生成しない。
3. 全キャストの比較から、各人物の外見・性格の根拠・行動傾向と、人物間の共通点/差を決める。
   比較表の各行を独立に生成するのではなく、全行を見た作者が組み合わせを設計する。
4. 全体設計をstableな人物IDへ結び、個別character bible、p500の生成requestへ投影する。
   個別画像の生成後も、混同しやすい人物を並べて作者が確認する。
   別エージェントの採点や常設のユーザー承認を必須工程にしない。

## 定義すること

| 軸 | 設計する内容 |
| --- | --- |
| 役割と関係 | 物語で何をする人か、誰とどんな関係か、観客が区別すべき理由 |
| 根拠 | 原作の事実、行動からの解釈、演出上の補完を別々に記録する |
| 性格と振る舞い | 判断や対人反応の傾向、話し方、姿勢、所作、感情の出方。sourceを越える動機や過去は創作しない |
| 外見 | 年齢感、顔の輪郭と特徴、髪、体格・シルエット、衣装の形・素材・色、識別の手がかり |
| 意図した共通点 | 家族の顔立ち、同じ組織の制服、同じ世界の服飾様式など、似せる理由 |
| 区別点 | 混同しやすい相手のIDと、どの外見/振る舞いで見分けるか |
| 継続する状態 | 同じ顔・体格として保つ要素と、着替えや変化後に引き継ぐvariant |

「勇敢」「誠実」などの抽象語だけで画像を生成しない。source上の性格を定義したうえで、
描画可能な姿勢や普段の表情などが必要なら、その演出上の表現を外見欄に具体化する。
性格は全shotの表情を固定する指定ではない。各場面の行為・反応・感情が優先される。
悪役だから醜くする、脇役だから特定の年齢にする、といった固定対応表は作らない。

## 見分けるための設計

- 色だけに頼らない。顔が近づいた画、全身の遠景、暗い室内でも区別できる組み合わせを選ぶ。
  すべての軸を変える義務はないが、同じ髪・顔・シルエット・装飾へ重なる理由を点検する。
- 役割の違いが重要な二人は、衣装の格式や構造、顔や髪の形、姿勢などを比較して決める。
  「別人」「主人公と似せない」だけを、個別画像の具体的な設計の代わりにしない。
- 家族や同僚は似ていてよい。共通する特徴と、個人を見分ける特徴を両方持たせる。
  双子・変装・意図した混同などsourceが要求する場合は、その意図と判別可能になる時点を保持する。
- 集合人物にはmember IDを持たせ、人数と各memberの顔・髪・衣装・行動傾向を分ける。
  一人分の顔を複製して複数人の正本にしない。画面の左右は人物IDの代わりにならない。
- 人間以外には種に適した外見を定義する。sourceにない人間の顔・衣服・擬人化を足さない。
  変化後の姿はstate variantとして前後の対応を設計し、別人を無関係に追加しない。
  年齢・顔・髪・体格が維持されるかは変化の内容ごとに決める。動物から人間への変化や
  加齢・髪型変更に、変化前の外見欄を「固定する特徴」として一律に足さない。
- 比較のために読んだ全キャラ画像を、個別生成の同一人物参照として無差別に送らない。
  実際に送る画像は対象人物のidentity、衣装状態、比較用などの役割を分ける。

## 保存と投影

全体で定義した人物ID/member、表示名、外見の識別点は、画像だけでなく後続の
[人物別の行為設計](shot-direction.md#人物と行為を個別に結び付ける)へ渡す。
同じ画面にいる人物同士で、誰が行うかによって意味が変わる行為と道具を確認する。
全体設計の役割・所作を参照しつつ、各shotで行為主体、対象、道具の保持者、周囲の反応を
既存のsubject/performance欄へ具体化する。画像用promptはその瞬間の外見・姿勢・手元、
動画用promptはその人物の動作と相手の反応として書き分ける。外見を区別したことだけで
動作の主体も正しく伝わったとは判断しない。全員へ同じ場面説明をコピーせず、性格や役職から
その場にない行為を自動的に補わない。

全体設計は `cinematic_direction.json` の `cast_design` に保持する。
`cast_design_v1` の `characters` は最終resourceの `character_id` をキーとする。
型・必須値・参照ID・人数・source bindingを現行runtimeで検証し、文章の善し悪しを
キーワード判定や品質点数へ置き換えない。構造の例は
[キャスト設計テンプレート](../../workflow/cast-design-template.yaml)を参照する。

- 共通: `character_id`、`name`、`role`、`subject_contract`、`relationships`、
  `personality_provenance`、`behavior_baseline`、意図した類似性と比較する相手。
- `role_basis` と `contract_reconciliation` に役割・人数の根拠を残す。
  reconciliationは `status`（consistent/contradicted/underdetermined）、`source_basis`、
  `explanation` を作者が書き、runtimeが元の `legacy_subject_contract` と
  `existing_reference_images` を保持する。古いcount-oneの初期値をsource上の人数より優先しない。
- 個人: `appearance`、`appearance_provenance`、`intentional_similarities`、`distinguish_from`。
- 集合: `shared_appearance` と `members`。memberごとに外見と根拠、行動、共通点/区別点を持つ。
  `members[].member_id` を `subject_contract.member_ids` と人数へ一致させる。
- 外見欄: `age_impression`、`face_shape`、`hair`、`build_silhouette`、
  `palette_costume`、`identifying_features`。種や人物に当てはまらない項目は、理由を明示する。
- 性格の根拠: `source_facts`、`interpretation`、`creative_choices` を区別する。
  対象人物に根拠がない性格は、原作で断定されているように書かない。
- `appearance_provenance` / `shared_appearance_provenance` も同じ3区分を持つ。
  比較先は `intentional_similarities[].with_id` と `distinguish_from[].with_id` で指定する。
  `reference_identity_bindings` は既存の読める参照画像のpath/hashをruntimeが設定する。

個別character bibleとasset planには、この設計に基づくappearance contractを渡す。
画像APIへは描画可能な外見と必要な区別点を投影し、source ID、監査情報、長い人物論を
promptへ連結しない。集合人物はmemberごとに描画内容を分ける。
関係・性格の根拠・行動傾向は全体設計に保持し、後続の演技設計で参照する。
個別画像を作るたびに別の人物像を考え直さない。

source、最終resource一覧、採用参照、人物設計が変わった場合は、その入力へ結び付いた
設計cache/requestを再評価する。生成済み素材を無断で再生成せず、変更の影響範囲を示す。
既存runに `cast_design` がないだけで合格素材を無効にしない。会話から既存作品を直すときも、
全キャストを比較してから必要な人物だけを変更候補にし、現行採用版と区別する。

人数設定を修正しただけで既存画像も正しくなったとは扱わない。古い集合参照が一人分なら、
実画像と採用範囲を確認し、誰の参照として使えるかと不足するmemberを区別する。

終了画像の指定は別の動画設計判断である。この工程を理由に全cutへ終了画像を足さない。
