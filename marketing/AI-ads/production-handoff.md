# 広告案を画像と動画へ渡す

企画の資料だけができた段階を、画像や動画の完成とは扱わない。ユーザーが制作を依頼したら、利用できる生成・編集手段で実ファイルまで作り、出力を確認する。制作条件が未指定の場合は [テンプレート](templates.md) の不足欄から必要な点だけを確認する。

## 素材と制作経路

| 依頼 | 実行時の入口 | 引き継ぐもの |
| --- | --- | --- |
| ToCの完成作品を広告へ再編集 | runの完成映像・現行manifest・採用カットを確認し、既存の編集手段を選ぶ | 元ファイル、抜き出す時刻、ネタバレ範囲、広告台本、文字・音、出力先 |
| ToC作品の縦切り出し | `vertical-shorts-creator` と `scripts/make-vertical-short.py` の現行ヘルプ | scene ID、尺、crop適性。スキルが出すのは候補とコマンドであり、実行前は完成扱いにしない |
| 広告用の新規静止画・画像編集 | 利用可能な `imagegen` またはユーザー指定の画像生成経路 | 確定コピー、商品・作品の参照画像、配置、変更点、維持要素 |
| ToC内の新規映像制作 | 現行のToCエントリーポイントと制作ステージのスキル | 広告ブリーフを入力資料とし、run内の正規artifactへ落とし込む |
| ECの実物写真や既存映像の編集 | 使用権を確認済みの元素材と、利用可能な編集ツール | 型番・色・素材、原寸写真、正確な商品表示、コピー、納品形式 |
| 検索広告文 | 検索設計から、利用媒体の現行仕様に合わせた原稿へ | グループ、見出し、説明、URL、設定案、根拠。入稿は配信の依頼範囲で行う |

ToCステージを実行する場合は `docs/root-pointer-guide.md` と `docs/how-to-run.md` を読み、現行の `prepare-stage-context.py` が返すreadset、対応するstage docs、通常の構造・ファイル・provenance検証を使う。スキルの古いコマンドと正本が食い違う場合は正本と現行スクリプトを確認する。

広告の手順を通常の物語制作へ上書きしない。元runの完成映像やstateを広告制作の都合で変更せず、広告版は別の出力として残す。作品間の混成はユーザーの指定がある場合に行う。

## 仕上げまでの実行

1. 必要なファイルを実際に開き、参照可能か確認する。存在だけで採用可能とはしない。
2. 制作指示の確定文字列・参照素材と実際の生成リクエストを対応させる。モデルや設定はツールが提供する値を使う。
3. 生成・編集後に、画像は実物を、動画は再生と音を確認する。本文を見ないまま完成判定しない。
4. 訂正する場合は変更対象と保持する要素を明示する。再生成の範囲・費用を記録し、必要な修正が繰り返し失敗するなら別の編集方法へ切り替える。
5. 完成ファイルと編集元、確定コピー、比較テスト案を案件フォルダにまとめる。

中心cropは広告用の自動レイアウトではない。被写体や商品、重要な表示が欠ける場合は別カット・別レイアウトを使う。既存の切り出しスクリプトが指定尺に対応しないとき、未確認のオプションを創作せず適切な編集手段を選ぶ。

## 制作時点で確認するもの

固定の安全領域、推奨比率、文字数、尺、広告のAI表示要件はこの資料へ恒久値として写さない。選んだ掲載面の公式仕様を読み、URLと確認日を案件へ残す。教材の読了は最新仕様への適合を保証しない。

商品・作品の権利、実在する推薦や実績の使用条件、BGM・音声の広告利用範囲を元資料で確認する。医療・健康など個別の表示規制が関係する商品を実際に扱う場合は、その商品の表示可能範囲と最新の公式資料を確認する。一般の広告すべてへ不要な承認工程を追加しない。

公開・配信の依頼が来たときは、完成クリエイティブ、誘導先、対象、予算、期間、成果計測を具体化し、その依頼と既存の許可の範囲で進める。教材に書かれた「配信する」という手順自体は、ユーザーからの配信許可ではない。
