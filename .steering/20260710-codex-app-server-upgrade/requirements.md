# Codex app-server upgrade requirements

## Goal

Frontend create, chat, semantic review, prompt repair, and image generation must all use the current Codex app-server runtime and the latest approved Codex agent model through the shared backend boundary.

## User journeys

- As a frontend user, I want chat and generation requests to use the latest approved Codex agent so that different backend paths do not silently inherit an older personal default.
- As an operator, I want server startup to reject an obsolete Codex CLI so that protocol drift fails before a production turn starts.
- As a maintainer, I want runtime diagnostics to record the effective CLI version, minimum version, and model so that failures can be reproduced.

## Success criteria

- The machine Codex CLI/app-server is upgraded from `0.133.0` to `0.144.0`.
- `server/codex_app_server.py` remains the only production app-server runtime boundary.
- All threads default to `gpt-5.6-sol`, with `TOC_CODEX_APP_SERVER_MODEL` retained as an explicit override.
- Preflight rejects CLI versions below `0.144.0`, with `TOC_CODEX_APP_SERVER_MIN_VERSION` retained as an explicit override.
- Runtime diagnostics contain the detected CLI version, required CLI version, and effective model.
- Existing frontend create, chat, semantic review, prompt repair, and image generation call sites require no per-feature model literals.
- Relevant unit tests and a real app-server initialize/model/thread/turn smoke test pass.

## Scope

- `server/codex_app_server.py`
- `tests/test_image_gen_server.py`
- `docs/system-architecture.md`
- this steering directory

## Out of scope

- Historical run artifacts, fixtures, and completed steering documents
- Non-Codex provider models
- Frontend visual changes
- Changing the frontend chat payload contract

## Evidence

- Official Codex app-server protocol and `model/list` documentation
- Official latest-model guidance naming `gpt-5.6-sol`
- Schema generated by Codex CLI `0.133.0` and `0.144.0`
- Live `model/list` response from the upgraded local app-server
