# Resume rejected image preparation with bounded revisions

## Requirement
Completed image candidates can fail the preparation author's visual confirmation.
The existing checkpoint keeps this result permanently and ordinary retry cannot
revise the rejected plan. Preserve those receipts and files while allowing an
explicit, bounded revision using the actual rejected images and recorded feedback.

## Design
- Add review_revision (0 default, maximum 3) to shared API/CLI/service options.
- Revision N requires revision N-1 to have a needs_input image review for the
  same original source snapshot, fixed images and selected model.
- Reconstruct and verify the rejected draft images against source hashes and
  completed image receipts, then attach them to the author with the feedback.
- Merge corrected cut plans into the previous proposal to preserve valid work.
  Never accept unchanged as a way to erase a failed review.
- Keep each revision in its own checkpoint; reuse matching image receipts,
  preserve cumulative budgets, protected narration/timing and publication checks.
- No automatic revision loop, no new run, no deletion/reset of histories.

## Checks
Regression tests: feedback/context propagation, old receipt preservation,
missing/invalid parent rejection, byte drift rejection, bounded revision and
no duplicate generation when resuming an existing revision. Review incremental
diff before production use. Use current cumulative budget for planning first.

## Verification

### Follow-up: planned references are not generated bytes
The real revision changed a starting image used by an ending image. Comparing
all request hashes before generation attempted to read that future start file.
Compare planned image conditions without reading new references at this point;
retain exact reference-byte hashing immediately before each dependent submission.
Migrate existing revision checkpoints by reconstructing the verified prior plan,
without another author call or deleting receipts. Add a start-to-end regression.
