# Requirements: Transformation State Asset Binding

## Background

Scene image and video requests can describe a state change while the asset inventory only contains
the pre-change identity. The image model then invents a result, and video requests may receive only
their first frame even when the authored motion requires a visible transformed result.

## Goals

1. Let the production author define source-grounded state variants for existing assets when the
   story requires a reusable visual result state.
2. Generate those required variants during the asset stage and bind their actual run-relative image
   paths and content hashes into scene image and video requests.
3. Materialize first/last-frame conditioning for providers and modes that support it; stop with a
   selector-specific structural error when a required result reference is absent or unsupported.
4. Use the same runtime contract from frontend create and Codex conversational production paths.
5. Preserve existing non-transformation manifests, accepted assets, and ordinary validation without
   adding a subjective quality gate or regenerating unrelated runs.

## Constraints

- Transformation design and what counts as the visible result belong to the authoring stage and must
  remain grounded in the current story/script/scene contracts.
- No title-specific names, entity maps, scene maps, or static keyword triggers in runtime code.
- Do not edit existing production outputs or generated media.
- `AGENTS.md`, `CLAUDE.md`, and `docs/root-pointer-guide.md` are not to be changed.

## Success Criteria

- A declared required state variant has source selectors, a parent asset identity, a drawable prompt,
  a destination, and request-bound generated bytes before dependent scene requests are materialized.
- Scene image references select the declared variant and are bound by path/hash in the immutable
  request snapshot.
- A declared video result frame is copied into the provider request binding as `last_frame`, with its
  content hash, only when the selected provider mode supports the boundary.
- Missing or unsupported required result references fail with an actionable selector and owning
  contract name; legacy requests without the new declaration continue to work.
- Focused tests cover authored variant parsing/materialization, scene image binding, video result
  binding/capability failure, and the shared frontend/Codex entrypoint path.
