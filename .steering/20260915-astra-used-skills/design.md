# 設計

- 期間内の state DB と rollout JSONL を照合し、実使用と保守目的の閲覧を分ける。本文の引用や他タスクの内容は保存せず、証跡のパス・行・日時だけを記録する。
- 14種類の利用済みカスタムスキルを更新する。既存の同名配布先は同じ改訂へ同期する。短い工程スキルは維持する。
- 開発パターンの例は用途別 references に分ける。固定のテスト量・15分ごとの再検証・汎用的な全手順読込を除き、対象変更の振る舞いで検証範囲を決める。
- ToC の根拠・request binding・provenance・append-only state・ロック・p650/p500 の再開境界を保持する。詳細な p500 CLI 手順と生成時の完了条件は必要な時だけ読む。
- goal-forge は既に決まっている条件を再承認させず、未決の製品判断だけを質問する。旧モデル・固定コンテキスト長・広い実行権限を readiness の必須条件から外す。
- restart は確認だけの依頼で再起動しない。review は指摘のみと修正依頼を区別し、適用中のサブエージェント方針を優先する。
- 編集前の全対象ディレクトリを /tmp/astra-skills-20260915/backup に保存する。変更を一時ディレクトリで作成・検証し、元ファイルの hash が一致する場合だけ適用する。
- 検証は frontmatter、内部リンク、配布先の一致、対象外ファイル不変、差分確認、既存 pointer validator と shared skill tests に絞る。生成APIやサーバー再起動は行わない。
