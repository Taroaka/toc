# p300：原作を保持する映像設計 — 要件

作成日: 2026-09-17。状態: 設計済み・実装未着手。

## 依頼と目的

ユーザーの依頼は、p300が物語を抽象化しすぎる問題と、JSON/YAMLの必須キーが
不要な葛藤・象徴・演出を作らせる問題を修正するため、必要な要素から設計すること。
今回は要件・設計・実装手順を成果物とする。

『ライト、ついてますか』に関する会話から採用する設計上の解釈は、状況を判断する
手掛かりを提供し、状況に依存する答えを一律に強制しない、というもの。
本書の紹介・目次: https://www.hanmoto.com/bd/isbn/9784320023680
以下のp300設計はこの会話を踏まえた本リポジトリ独自の設計である。

目的は、物語とユーザーの映像方針を読み、映像化で必要な判断を作品に即して加えること。
記入欄の充足、意味の増幅、毎場面の感情変化を目的にしない。作品固有の演出、壮観、
ユーモア、沈黙、曖昧さを選べる余地は残す。

## 必要な要素

| 要素 | 必要な理由 | 記録の方針 |
| --- | --- | --- |
| 入力とシーンの参照 | 物語・事実・開示順を失わず、どの入力を読んだかを追える | 機械的なID・パス・digest。上流本文は直接読む |
| 全編の見せ方 | ユーザー指定や作品固有の表現方針を共有する | 判断がある場合だけ自由記述 |
| 場面固有の演出 | 映像化で失われる情報を保ち、必要な表現を選ぶ | シーンに紐づく自由記述。空の配列を正常として扱う |
| 場面間の一貫性 | 人物・物・場所・状態を同じものとして認識させる | 必要な対象・場面・保持内容だけ記す |

## 必須要件

- R1: `research.md` と `story.md` の本文・source registry・scene/event/reveal/handoffを直接読む。
  scene title、motif、主人公名だけのprofileを本文の代替にしない。
- R2: p200が出来事、人物関係、意味、結末、場面順の正本である。p300はそれを要約文で置換しない。
  p400もstory本文とp300の両方を読む。
- R3: 全シーンの対応を確認するが、各シーンの演出メモは空でよい。
  未出力・author失敗・source不一致を「追加判断不要」とみなして補完しない。
- R4: 葛藤、相反感情、象徴的瞬間、救済、反転、時間圧力、全5領域の演出を毎場面に要求しない。
  肯定的変容や不可逆な変化をp300の完了条件にしない。
- R5: 必要な判断は、誰・何・どの状況に対する見せ方かが分かる具体的な文で書く。
  感情や主題の語を禁止しない。問題のない場面にも問題説明を作らせない。
- R6: コードは構造と参照を処理する。作品の解釈・配色・演技・編集・価値IDの割当を定型文で創作しない。
- R7: source ID、event所有、順序、reveal、provenanceを保持する。
  adaptationの原作価値は上流から参照し、場面の位置や配列順で割り当てない。
- R8: p300で本番cut ID、cut数、秒数、provider prompt、生成request、素材画像を確定しない。
  同一性・参照素材への要求は場面・上流対象の単位で渡す。
- R9: p400以降が旧amplification欄を自動復活させない。必要な読取側変更も同じ実装範囲に含める。
- R10: 通常の構造検証で進む。critic、品質スコア、チェックリスト完答、別authorの証明書を加えない。
- R11: 新規runは新形式、既存runは旧形式で継続できる。既存成果物・state履歴を自動書換えしない。
- R12: frontend、CLI/assistant経路で同じauthoring規則とvalidatorを使う。

## 対象範囲

対象はp300のガイド・テンプレート・authoring実装・構造検証、およびp300依存の
p400/manifest引き継ぎ、source ledger、再開時の版整合性である。
p310/p330、`visual_value.md` という成果物名は維持する。

p200の物語再設計、p400全体のscene/cut契約再設計、既存run一括移行、画像・動画生成、
DB/UI改修は今回の設計対象に含めない。p400にも独立した定型演出が存在するため、
p300改修だけで全パイプラインの定型化がなくなるとは扱わない。

## 成功判定

1. シーンをすべて参照し、演出メモがすべて空の新形式を構造検証できる。
2. 同じ形式で、必要な一場面だけに演出や一貫性の指定を持たせられる。
3. source本文・ID・順序・入力digestの不整合は通常の構造エラーになる。
4. 新規経路に固定の尊厳/証明/解放、月白/金色、時間制限の光、序盤/終盤によるvalue割当がない。
5. p300→p400→manifestで出典と必要なメモを追跡でき、旧必須欄を捏造しない。
6. 既存v1のfixtureと再開経路は従来契約で検証でき、未知版・混在・stale入力は拒否する。
7. 静かな場面、救済のない結末、喜劇、語りが必要な場面、強い視覚演出が必要な場面を扱える。
   意味の忠実さは開発時の例比較で確認し、自動テスト合格と同義にはしない。

判断基準: 新しい欄・検証・工程を加える前に、それが後工程の具体的な判断または参照整合性に
必要か確認する。同じ内容を別の抽象語で再記述するだけなら追加しない。
