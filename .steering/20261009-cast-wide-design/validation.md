## Path activation and limits

The production function defaults `enable_cast_design=False`. The Codex authoring script passes `enable_cast_design=True` unconditionally, and the default frontend cinematic-authoring wrapper invokes that script. Thus the normal frontend and CLI authoring paths enable the pass; direct Python callers must opt in.

Readable existing character-reference files are bound by path and SHA-256 in the cast cache and direction artifact. Replacing bytes at the same path invalidates the cache and makes `load_direction` stale. The cast-design stage does not write reference images or invoke image/video generation. Visual compatibility with accepted image content is not compared by code; the author is instructed to preserve it, and any later image request uses the reference inputs present in its request contract. There is no approval gate in this pass. Runs without `cast_design` remain valid, and existing media are not regenerated by this stage.
